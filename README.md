# スクロール本棚 / Scroll Manga Shelf

スクロール漫画の作品URLをまとめ、サムネイル付きカードで探す個人用Webアプリ。Codex Cloud で続けて開発できる初期構成です。

## できること

- HTTPSリンクを1回30件まで一括登録、重複を除外
- OGP / Twitter Card からタイトル・説明・サムネイルURLを抽出
- レスポンシブなカード一覧、タイトル・サイト検索、画像の有無による絞り込み
- 画像の再取得、リンク削除、JSON書き出し
- SQLiteに保存。画像取得に失敗してもリンクは保持
- LINEマンガ・ピッコマ・comico・WEBTOON の公式サイトへの探索リンク

## 開発開始

Node.js 24 が必要です。

```bash
npm ci
npm run dev
```

http://localhost:5173 を開きます。ビルド済みUIは次のコマンドで http://127.0.0.1:3001 に起動できます。

```bash
npm run build
npm start
```

```bash
npm run check   # 型チェック・テスト・ビルド
```

必要に応じて `.env.example` を `.env` にコピーして設定します。APIキーは不要です。

## 取得の仕組みと制約

作品ページのURLを登録すると、公開HTML内の `og:image` → `twitter:image` / `twitter:image:src` の順で画像URLを探します。ページのスクリーンショットや漫画本文のダウンロードは行いません。画像は配信元URLをブラウザから参照し、取得できないときは代替カードを表示します。

自動取得は `.env.example` の4ホストに限定します。別サイトのリンクも保存できますが、取得対象にするには管理者が `METADATA_ALLOWED_HOSTS` に信頼できる完全一致ホストを追加してください。ワイルドカードは非対応です。リンク先の利用条件・自動取得方針を確認して利用してください。

JavaScript描画・ログイン必須・Bot制限があるサイトでは取得に失敗する場合があります。各公式サービスの全作品・全ページでの動作は保証しません。転送先も許可ホストに含まれる必要があります。HTMLは `</head>` までで読み取りを終了します。取得上限は10秒・先頭1MiB・3回転送、同時2件です。UIからは順番に取得します。

現時点では「公式サイトを横断して全作品を自動巡回」する機能やJSON再インポートはありません。気になる作品のURLを登録する方式です。初期の本棚は空です。

## データと運用

保存先は `data/shelf.sqlite`（`DATA_DIR` で変更可能）。`data/` と `.env` はGit管理対象外です。バックアップにはJSON書き出し、またはサーバー停止後の `data/` ディレクトリ保存を利用してください。

認証なしの個人開発用です。APIは既定で127.0.0.1にのみバインドします。インターネット公開前に認証とデータ分離を追加してください。
